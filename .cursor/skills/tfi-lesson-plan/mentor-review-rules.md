# Mentor review rules (from Google Sheets comments)

Source: Ashitha Sivadas review threads on `Grade 7_ Maths _Khansa LP` (CH2 + CH3 and related). Treat these as **must-pass** checks when generating or revising LPs.

## Voice (plan language)

| Prefer | Avoid |
|---|---|
| `Asking:` / `Writing:` / `Concluding:` | `Ask:` / `Write:` / `Conclude:` as bare commands |
| `Students:` expected lines | “Expected response:” as coach note |
| `Pairs are writing…` / `Moving around the groups.` | “Teacher circulates; minimal talk” / “Lead to:” / “Make sure you…” |
| Teacher-owned CH3-style dialogue script | AI instructing the teacher what to do |

## Completeness

| Mentor ask | Rule for the skill |
|---|---|
| “Please fill the same.” | Never leave required columns empty (concept, sub-concept, skill, SWBAT, vocab, hook, flow, CFU, graded, resources if used). |
| “The last two are not visible in the plan.” | Every listed sub-concept must appear as an explicit move in the flow. |
| “IP and GP are not visible” / “IP is missing” / “put the You do question here” | Label **WE DO (GP)** and **YOU DO (IP)** in the flow. Write the actual IP question stem(s) in the plan (flow + graded column as appropriate). |
| “Please put in the time for each section” | Every section has a minute budget. |
| “when will the students solve these? Please mention that in the flow” | State *when* practice happens (after I DO, during WE DO, as YOU DO, exit ticket). |
| “There are quite a lot of CFUs within the flow, please pick those and put here.” | Copy key in-flow checks into the **CFU / Ungraded** column with short answers. |
| “Please mention the question stem at the start” | Lead SPARK/Do Now / IP with the actual question stem, not a vague description. |
| “Please update the columns with chapter names of both part 1 and part 2” | Fill chapter/unit naming fields for all parts the sheet tracks. |
| Revision dates empty (“1/9, 2/9 revision plan to be updated”) | Revision periods still get a real plan (objective, hook, practice), not a blank concept cell. |

## Timing & calendar

| Mentor ask | Rule |
|---|---|
| “the time is 40 mins, flow is going beyond 40 mins” | Sum of timed blocks ≤ period length (default 40). If over, **split the SWBAT** across periods. |
| “why is the first 10 min given as an IP?” | Do not open with long IP. Open with Do Now / SPARK / short recap; IP comes after modeling and GP. |
| Weekend / no-class dates | Do not schedule lessons on Sundays or known non-teaching days; shift dates. |
| “timing is an issue… put down your reflections once class is done” | Ambitious timing is OK only if reflections capture what actually ran. |

## Alignment

| Mentor ask | Rule |
|---|---|
| “The IP is not aligned with the objective” | IP/graded items must assess the **same** SWBAT taught that period. |
| “The skill used for the assessment is not aligned with the learning outcome” | 3D Blooms skill ↔ SWBAT ↔ formative must match (e.g. Applying outcome → Applying skill + apply-type IP). |
| “break this learning outcome into two” (add then subtract) | One major operation/idea per period when both would overload. |

## Pedagogy & student ownership

| Mentor ask | Rule |
|---|---|
| GP builds ownership; “teacher talk is not ideally required”; circulate and help | WE DO = student/group work with light facilitation, not mini-lecture 2. |
| Prefer less teacher-led; “bring something hands on” | Prefer manipulatives, scales, visuals, group tasks over pure board talk. |
| “Can we have the hook more visual… Food works :)” | Prefer visual/contextual hooks; use textbook contexts when strong. |
| “teaching them all three methods is not necessary” | Default to **one** method in a period; extras optional if time remains. |
| Refresh anticipated breakdowns 2–3 mins (e.g. mixed ↔ improper) | Insert short prerequisite refresh when the main flow depends on it. |
| Recap before main flow when struggle was mentioned | If teacher notes struggle (e.g. tenths→hundredths), add a short recap before new content. |
| Word problems as major classroom breakdown → use **in class**, not HW | Hard word problems stay in I DO / WE DO / IP in class; HW = simpler practice. |
| “elaborate more on how are you going to breakdown word problem” | Script the breakdown steps (what to underline, what to convert, what to compute). |
| Hook language “might be a bit tricky… bring mixed fractions to the same situation” | Keep SPARK language simple; extend familiar situations rather than abstract jumps. |

## AI & ownership

| Mentor ask | Rule |
|---|---|
| “using AI is completely fine, but copy pasting an AI plan is not recommended… enhance our own plan” | Ground plans in teacher-chosen examples, textbook pages, and class realities. AI helps structure and wording only. |

## After delivery

| Mentor ask | Rule |
|---|---|
| Put reflections after class | Remind: fill Section A1 / A2 reflections post-lesson (what worked, what to reteach). |

## Quick fail list (reject / rewrite if any true)

1. No visible YOU DO / IP question
2. IP does not match SWBAT
3. Timed total > period length
4. Sub-concepts listed but absent from flow
5. CFUs only inside prose, missing from CFU column
6. Opens with long IP and no hook/recap
7. Three full methods taught in one 40-min period
8. Hard word-problem first exposure assigned as homework
9. Blooms skill mismatches assessment
10. Empty mandatory columns or weekend lesson dates
